# STM32 OTA Bootloader

基于 STM32F103ZET6 的 OTA Bootloader 示例工程。Bootloader 启动后会读取
EEPROM 中的升级标志，必要时把存放在外部 SPI Flash 中的固件复制到片内
Flash，然后跳转到主程序；也可以通过按键进入默认程序。

本仓库中的 Bootloader 负责“检查升级包、写入片内 Flash、跳转程序”。
升级包下载到 W25Q32 的过程，以及升级标志的写入过程，需要由主程序、
上位机或生产工装完成。

## 功能

- 从 W25Q32 外部 Flash 读取待升级固件
- 将固件写入 STM32 片内 Flash 的主程序分区
- 使用 W24C02 EEPROM 保存升级状态和校验密钥
- 升级后跳转到主程序，或跳转到默认恢复程序
- 通过 PF8 按键触发恢复默认程序
- 跳转前检查栈顶地址和复位向量
- 提供 W25Q32、W24C02 的基础读写和擦除接口

## Flash 分区

片内 Flash 按以下方式划分：

| 区域 | 起始地址 | 结束地址 | 大小 | 用途 |
| --- | --- | --- | --- | --- |
| Bootloader | `0x08000000` | `0x08003FFF` | 16 KB | 启动、升级和跳转 |
| 默认程序 | `0x08004000` | `0x08007FFF` | 16 KB | 恢复/出厂程序 |
| 主程序 | `0x08008000` | `0x0807FFFF` | 480 KB | 正常运行的程序 |

主程序工程需要链接到 `0x08008000`，并保证中断向量表也位于该地址。
Bootloader 跳转前会设置：

```c
SCB->VTOR = app_start_addr;
```

## 启动与升级流程

1. 初始化 GPIO、USART1、I2C2 和 SPI1。
2. 从 W24C02 地址 `0x10` 读取 3 个字节：升级状态和 16 位密钥。
3. 校验密钥是否为 `0x5A6B`；密钥错误时将状态恢复为“不升级”。
4. 等待约 3 秒，期间按下 KEY1 会把本次启动状态改为“恢复默认程序”。
5. 根据状态执行操作：
   - `0x01`：从 W25Q32 读取固件并写入片内 Flash。
   - `0x02`：不升级，直接进入主程序。
   - `0x03`：跳转到 `0x08004000` 的默认程序。
6. 跳转前关闭 Bootloader 使用的中断和 SysTick，设置 MSP 和向量表后跳转。

## W25Q32 升级包格式

W25Q32 的地址 `0x000000` 开始存放 8 字节元数据：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| `0x00` | 4 字节 | 固件在 W25Q32 中的起始地址，小端序 |
| `0x04` | 4 字节 | 固件长度，小端序 |

固件本身必须从元数据指定的地址开始存放，起始内容为标准 STM32 中断向量表：

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| `0x00` | 4 字节 | 初始栈顶地址，必须位于 `0x2000xxxx` |
| `0x04` | 4 字节 | Reset_Handler 地址，必须位于 `0x08008000` 到 `0x0807FFFF` |

当前工程约束：

- 固件起始地址不能小于 `0x00001000`，避免覆盖元数据所在扇区。
- 固件长度范围为 500 字节到 `0x78000` 字节。
- 升级目标固定为片内 Flash 地址 `0x08008000`。

例如，固件从 W25Q32 的 `0x00001000` 开始存放，长度为 `0x00004000`
字节，则元数据为：

```text
00 10 00 00 00 40 00 00
```

## W24C02 升级状态

Bootloader 从 EEPROM 地址 `0x10` 开始读取 3 个字节：

| 地址 | 内容 |
| --- | --- |
| `0x10` | 升级状态 |
| `0x11` | 密钥高字节 `0x5A` |
| `0x12` | 密钥低字节 `0x6B` |

升级状态定义：

| 状态值 | 含义 |
| --- | --- |
| `0x01` | 执行升级 |
| `0x02` | 不升级，直接进入主程序 |
| `0x03` | 恢复默认程序 |

触发一次升级时，向 EEPROM `0x10` 开始写入：

```text
01 5A 6B
```

升级流程开始后会清除 `0x10` 的状态值，避免每次复位重复写入固件。

## 编译

1. 安装 Keil MDK 和 STM32F1 器件支持包。
2. 打开 `code/bootloader_hal/MDK-ARM/P02_bootloader_hal.uvprojx`。
3. 选择目标 `P02_bootloader_hal`，执行 Rebuild。
4. 编译成功后生成：

```text
code/bootloader_hal/MDK-ARM/P02_bootloader_hal/P02_bootloader_hal.hex
```

仓库中的构建记录显示该工程曾使用 Keil MDK 5、ARMCC 5.06 编译通过。
其他工具链使用时，需要同步维护启动文件、链接地址和散列文件。

## 烧录

1. 使用 ST-Link、J-Link 或其他 SWD 工具连接 PA13、PA14、GND 和 3.3V。
2. 将 `P02_bootloader_hal.hex` 烧录到片内 Flash 起始地址 `0x08000000`。
3. 烧录默认程序和主程序，确保它们分别链接到 `0x08004000` 和
   `0x08008000`。
4. 将升级固件和元数据写入 W25Q32。
5. 向 W24C02 写入升级状态 `01 5A 6B` 后复位设备。

USART1 当前主要用于调试输出，仓库中未实现通过串口接收 OTA 固件的传输
协议。

## 注意事项

- 当前仅校验中断向量表中的栈顶地址和复位向量，没有对完整固件计算 CRC。
- 当前没有双备份和失败回滚机制，升级过程中断电可能导致主程序不可用。
- 元数据校验失败时只输出错误信息，实际产品中应中止擦写流程并保留原程序。
- W25Q32 写入接口默认一次写入不超过一页，使用前应按实际数据长度分页处理。
- 修改 Flash 分区、升级地址或固件大小限制时，需同时检查链接脚本、
  `Int_bootloader.h` 和 `App_bootloader.h`。
